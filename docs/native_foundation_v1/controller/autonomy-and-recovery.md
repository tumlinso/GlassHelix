# NF1 execution and recovery charter

GH-NF1-A04 adopts the user-authorized engineering autonomy in the paired NF1
packages. One strategic controller selects the ready frontier in two independent
project authorities. Ordinary implementation, algorithm selection, justified
refactoring, provisional API changes, regression repair and cleanup within the
program do not require renewed user approval. This charter does not settle
scientific uncertainty or authorize a next biological experiment.

Before each assignment, inspect the current task, local lane queue, dependencies,
claims, dispatch, managed workspace, Git head/dirty work and producer receipts.
Keep one serial task active per lane. A collaboration agent is first class only
with its native project-qualified claim/dispatch; local workers do not substitute
for lanes. A stale heartbeat requires live observation/sync, not unilateral
restart or deletion. Use opaque workflow handles and current supported APIs.

A scope adjustment is a coordination transaction: identify the existing owner,
needed path/capability, competing claims and affected consumers; record the
rationale and new scope through supported native operations; refresh task context
before editing. If no ordinary surface supports a correction, use explicitly
authorized owner maintenance with fresh revision checks and preserved evidence.
Never edit SQLite, generated Markdown or recovery snapshots as a second ledger.
Do not duplicate a stronger existing Cellerator implementation to evade scope.

For developmental interfaces, record the new version and content/source hashes,
name consumers and affected tests, update those consumers, and invalidate stale
receipts. Equal shape, source filename stability or a descendant commit alone
does not establish semantic compatibility. Preserve role identities, assertions,
effects, primal generations, support epochs and numerical/nonfinite behavior.

Seed a real native calculation and real test registration early. A reference
model checks the implementation but does not replace it. A descriptor or fake
provider never closes runtime work. The central build owner integrates root CMake,
exports and consumer wiring; request a narrow transfer/prerequisite if that owner
would otherwise prevent a dependent executable test. Never accept empty CTest
inventory, skips or CPU fallback as required real CUDA evidence.

Budget CPU, memory and build jobs jointly across ready lanes. Obtain an actual
native GPU lease, verify its current owner/process/device identity, and hold the
single shared /tmp/nf1-20260908-v1-device-evidence.lock across both repositories
for device evidence/timing. Builds do not need a device lease. Missing devices
block the GPU gate while independent ready host work continues. Record negative
performance findings and preparation versus steady execution separately.

Commit meaningful work after its relevant checks. Publish native artifact and
handoff state, integrate producer commits into consumers, and push ordinary
fast-forward-safe checkpoints intermittently. Source-under-test identity belongs
in external receipts, avoiding self-referential source hashes. Imports verify
commit ancestry plus relevant source hashes, interface versions, actual tests and
fresh authoritative producer task/checkpoint state. Closure is CE M50 then GH M60,
CE M90 then GH M90; never introduce the reverse final dependency cycle.

Recover by reading live source, worktrees, claims, dispatches and test processes.
An observation timeout is not termination. Preserve pending patches and unknown
files; inspect before reassignment and rerun killed/failed qualification rather
than editing it to passed. No reset, clean, force-push or deletion of unrelated
historical worktrees. A failed push preserves the local commit and recovery
record. Final cleanup removes only owned worktrees proved merged; both origin/main
must contain the final qualified pair before program closure.

This charter is review evidence. It does not itself demonstrate a calculation,
resource reservation, completed cross-project receipt or final qualification.
