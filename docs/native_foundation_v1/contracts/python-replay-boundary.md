# Developmental Python and replay boundary, version 1

This is a specification for later Python/replay owners, not an implemented
Python API, binding technology choice or replay engine. Python must invoke the
same native scientific/numerical path and preserve the quantity, observation,
inferential and provenance roles in core/contracts.hh. Do not implement a second
Python numerical reference as the production provider.

Replay must pin scientific model/revision, source pair, Cellerator persistent
axes/structure epoch and value generations, units/scales, forcing and
integration/differentiated-object interpretation, masks and supported capabilities.
Unsupported stochastic/history/derivative routes remain explicit failures.
Serialize persistent identity fields according to the Cellerator ABI, never by
copying structs or treating hot handles as durable identity. A missing runtime,
source dependency or capability receipt blocks runtime replay acceptance.
