# Prospective mechanistic-toolbox example

`mechanistic_toolbox.cc` is a post-epic public native consumer, not today's implementation. Its default mode requires actual CUDA. `--cpu` is an explicitly different production backend test. The linked numerical work must run through GlassHelix and Cellerator; the independent `fixture.hh` formulas are used only as comparison oracles.

The generic system has four scalar coordinates, a three-input nonlinear mechanism, two separate parameters that enter as `a+b`, piecewise forcing and a partial observation. There are 33 independent instances to expose tail-width assumptions. It exercises shared definitions with independent value planes, RK4, selected observation JVP/VJP, a local rank-one sensitivity, masked/compacted support and a finite supplied-candidate inferential state. It makes no fibroblast or causal-identification claim.

The declarations in `planning/native-foundation-v1/contracts/include/GlassHelix/foundation.hh` exist only to syntax-check a proposed consumer surface. They are protected by a planning-only macro and must not be installed or used as an implementation. The implementing agents may revise API spelling through the developmental contract tasks while preserving the demonstrated semantics and assertions. No whole-demo function returning canned results may replace this program.

`reference_main.cc` is a separate executable which can run now. Build it with `-DGH_NF1_REFERENCE_ONLY=ON`. A passed reference test does not establish native linking, GPU correctness, general identifiability or performance. Normal configuration fails until the real GlassHelix package/target exists. Test names `gh_nf1_demo_cpu` and `gh_nf1_demo_cuda` belong to the post-epic integration acceptance.

The forcing changes at 0.75 exactly; interval splitting is part of the contract. An integration stage must not accidentally use the next interval's right-hand value to finish the previous interval. The derivative is of the implemented RK4 observation map, not of an exact continuous-time flow.

Statistical inference here only reweights two supplied alternatives. It is not mechanism search. A stable code identity is not evidence of molecular identity. Performance receipts must report actual preparation and allocation counters separately from these mathematical checks.
